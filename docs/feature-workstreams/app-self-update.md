# Встроенное обновление приложения

Дата: 8 сентября 2026.

Статус: утверждено для реализации 8 сентября 2026 ответом пользователя
«Ок, давай реализовывать?» после обсуждения канала без Developer ID.
Одобрены Sparkle, GitHub Releases, ad-hoc packaging и исключение Library
Validation только для приложения. Выпуск, генерация постоянного ключа и
публикация остаются отдельными действиями. Контракт записан в PRODUCT_SPEC.md.

## Подтверждённое намерение

Пользователь уточнил: обновлять само приложение, причём «приложение само
скачивает и устанавливает обновление». Проверка квоты и сброс лимита к этой
функции не относятся. Переход на страницу скачивания не заменяет выбранный
сценарий.

Дополнительное ограничение пользователя: Developer ID использовать невозможно.
Предлагаемый канал — GitHub Releases, ad-hoc приложение и отдельные подписи
обновлений Sparkle. Developer ID и notarization не являются условиями этого
дизайна. Исключение Library Validation ниже входит в одобренный вариант.

## Рекомендуемый срез

Одна команда «Проверить обновления…» в обычном меню строки меню запускает
стандартный интерфейс Sparkle 2. Пользователь выбирает установку предложенной
версии; приложение скачивает, проверяет и устанавливает её, затем перезапускается.
В первой версии новые проверки инициирует пользователь. Фоновые проверки,
самостоятельное скачивание будущих версий и предложение включить автоматику
отключены. Это полное обновление внутри приложения с ручным запуском процесса.

## Расположение и сценарий

Команда располагается в нижнем блоке обычного меню, перед «Выйти».
Кнопка доступна также при скрытом питомце и включённом пропуске кликов.
В первую версию не добавляются пункт Pixel-меню, кнопка внутри hover-карточки,
About-окно и глобальная клавиша.

Схема представительного макета; версии A/B обозначают пример перехода,
не назначают следующий номер релиза. Это не снимок работающего Sparkle.

```text
ОБЫЧНОЕ МЕНЮ             ДОСТУПНО ОБНОВЛЕНИЕ             ГОТОВО К УСТАНОВКЕ
──────────────────      Black Hole                     Black Hole
Проверить обновления…    Версия A → версия B             Обновление подготовлено
Выйти                   Что изменилось                 Установить и перезапустить
                        Установить обновление

NATIVE MENU             UPDATE AVAILABLE               READY TO INSTALL
──────────────────      Black Hole                     Black Hole
Check for Updates…      Version A → version B          Update prepared
Quit                    Release notes                  Install and Relaunch
                        Install Update
```

Окна и служебные кнопки берутся из стандартного Sparkle UI. Подписи выше
фиксируют смысл. Точные RU/EN строки, размеры и действия Cancel/Escape/крестика
проверяются в выбранной версии framework; собственная копия его окон не нужна.

### Смысл отмены

Первая команда установки разрешает загрузку и установку выбранного обновления.
Финальная команда выбирает немедленный перезапуск. В Sparkle откладывание
готового обновления может оставить установку на обычный выход из приложения;
`Dismiss` не равен отмене установки. Поэтому не вводить собственное «Позже» и
не обещать, что закрытие любого окна отменяет обновление. Штатные действия
отмены и закрытия требуется отдельно проверить на выбранной версии.
Основание: [SPUUserDriver](https://sparkle-project.org/documentation/api-reference/Protocols/SPUUserDriver.html).

## Поведение питомца и сохранность

- Все значения квоты, включая 0%, неизвестные и устаревшие данные, а также
  Standard/Turbo и подключение к Codex независимы от обновлятора.
- Открытие системного окна закрывает временную карточку/контекстное меню.
  Окно получает фокус по действию пользователя; постоянная Dock-иконка
  не добавляется. Сам питомец подчиняется текущим правилам видимости.
- S/M/L и Smooth/Pixel не меняют окно обновления. Питомец не перемещается
  во время проверки/загрузки, не проигрывает специальный эффект обновления.
- Клавиатура, VoiceOver, Reduce Motion, светлый/тёмный режим и контраст
  проверяются на штатном UI. Прогресс не должен непрерывно перебивать речь.
- Размер, стиль, Object Mix, фиксация, пропуск кликов, фильтр Codex, full-screen
  preference, настройка запуска при входе и локальная история сохраняются.
- Требование к перезапуску именно после обновления: сохранить также текущую
  ручную видимость и положение. Для этого достаточно одноразовой записи
  текущего frame/visibility и исходного/целевого build перед разрешённым
  завершением. Следующий запуск забирает запись один раз, применяет только к
  ожидаемому целевому build и удаляет; при отмене завершения запись удаляется.
  При смене дисплеев действует существующее ограничение видимой областью.
  Обычные перезапуски не получают нового постоянного режима восстановления.
- Перед завершением прекратить приём новых наблюдений и дождаться уже принятых
  операций записи истории. Атомарная запись файла уже есть; ожидания всех
  поставленных задач при выходе пока нет. При ошибке или тайм-ауте ожидания
  отменить завершение и установку; показать ошибку и возможность повторить
  обновление. Продолжать установку с несохранёнными принятыми данными нельзя.
- Если завершение отменено или ожидание записи не удалось, удалить одноразовую
  запись восстановления и возобновить обычное получение квоты/переподключение.
  После остановленного App Server восстановить непрерывность через обычный
  baseline/gap. Нельзя оставлять работающее приложение с остановленным сбором
  данных. При ошибке хранения сохранить прежнее предупреждение об этой ошибке.
- После запуска новой версии применять обычную свежесть/непрерывность истории:
  сохранённые значения не выдавать за новый ответ сервера.
- Закрывается только принадлежащий Black Hole процесс App Server. Codex Desktop,
  CLI и выполняемые ими пользовательские задачи не завершаются.

## Минимальная архитектура

Один `SPUStandardUpdaterController` на время жизни приложения через небольшой
адаптер в `Services`. `AppState` предоставляет доступность команды SwiftUI;
`AppDelegate` связывает показ и завершение с lifecycle. Sparkle владеет
скачиванием, проверкой, установкой и перезапуском. Не копировать его автомат
состояний, ZIP-распаковщик или установочный helper в код проекта.
Повторные проверки ограничивает `canCheckForUpdates`.
[Официальный способ подключения](https://sparkle-project.org/documentation/programmatic-setup/).

Для реализации закреплена стабильная Sparkle 2.9.6, опубликованная
17 августа 2026; версия и SHA-256 официального архива проверены через GitHub API.
Требуемые настройки: `SUEnableAutomaticChecks=NO`, `SUAutomaticallyUpdate=NO`,
`SUAllowsAutomaticUpdates=NO`, `SUEnableSystemProfiling=NO`,
`SUVerifyUpdateBeforeExtraction=YES`, `SURequireSignedFeed=YES`,
`SUSignedFeedFailureExpirationInterval=0`; JavaScript в release notes выключен.
Последний параметр сохраняет обязательность проверки feed при длительной ошибке;
потеря ключа потребует отдельного восстановления доверенного канала.
[Семантика настроек](https://sparkle-project.org/documentation/customization/).

## Канал и подпись

Предлагаемый постоянный адрес feed:
`https://github.com/danya-kim99/codex-quota-pet/releases/latest/download/appcast.xml`.
Сейчас такого asset нет. Feed будет содержать доступные совместимые релизы,
точные URL архивов своих версий, размеры и требования к системе/архитектуре.
Один пользовательский канал, без выбора beta/stable и без GitHub-токена клиента.

Сравнение версий выполняет Sparkle по растущему `CFBundleVersion`; отображается
`CFBundleShortVersionString`. Имя приложения и bundle ID сохраняются. Не
сравнивать даты релизов или версии как произвольные строки.

Архив и feed подписаны Ed25519; публичный ключ встроен в приложение, приватный
не попадает в репозиторий, приложение или логи. Release notes лучше встроить
в подписанный feed. SHA-256 сохранить для ручной проверки архива. Подпись
обновления и подпись приложения решают разные задачи.
[Публикация для Sparkle](https://sparkle-project.org/documentation/publishing/).

Канал без Developer ID: сохранить ad-hoc подпись приложения и проверку
происхождения обновлений собственным Ed25519-ключом. Sparkle допускает такую
дистрибуцию. Подпись Sparkle не заменяет notarization и не отменяет Gatekeeper;
отсутствие системных предупреждений при установке/запуске не обещается.

Для текущего сочетания ad-hoc + Hardened Runtime подключение Sparkle требует
отдельного исключения Library Validation:
`com.apple.security.cs.disable-library-validation=true` для приложения.
Остальные ограничения Hardened Runtime сохраняются. Это ослабляет проверку
происхождения загружаемых библиотек внутри данного приложения, не отключает
Gatekeeper или защиту macOS глобально. Исключение одобрено для реализации;
работоспособность должна быть проверена
на полном переходе между двумя ad-hoc сборками с корректно упакованными
вложенными компонентами Sparkle. Готовность текущего бинарника не предполагается.

Если исключение неприемлемо, потребуется отдельно оценить собственный механизм
проверки/замены/перезапуска без загружаемого стороннего framework. Такой вариант
существенно расширяет код и поверхность проверок и сейчас не выбран.
[Ограничение загрузки framework](https://sparkle-project.org/documentation/),
[разъяснение сопровождающего](https://github.com/sparkle-project/Sparkle/discussions/2466).

Публикационный процесс должен сначала собрать, подписать и проверить архив,
затем подготовить проверенный подписанный feed с заметками и только после этого
сделать полный релиз доступным через latest. Учесть, что текущий workflow
ожидает ровно два assets. Предыдущие совместимые записи feed сохраняются.
Переключение latest и выпуск более высокого build требуют отдельной проверки.

Добавляются только HTTPS-запросы к каналу обновления/архивам, включая штатные
GitHub CDN redirects. История, квота, запросы, проекты и идентификаторы аккаунта
не отправляются; профилирование отключено. GitHub получает обычные данные
сетевого запроса, поэтому текущий privacy-текст потребуется уточнить.

## Переход, сбои и границы

В 0.9.0 нет updater и доверенного ключа. Первую версию с этим механизмом нужно
установить один раз текущим ручным способом. Последующие версии обновляются
внутри приложения. В существующий релиз нельзя задним числом добавить кнопку.

Ошибки проверки/загрузки/подписи до установки оставляют работающую копию.
Прерывание замены проверяется интеграционно; не заявлять проверенным то,
что пока является критерием приёмки. Автоматический откат после падения уже
установленной новой версии не входит в срез. Для такого инцидента остаётся
восстановление доверенного архива или исправленный релиз с большим build.

Обновляется только текущая установленная копия. В продукт не переносится
workspace-правило поиска/удаления всех старых сборок: это отдельная операция
релизного агента. Исходники, другие приложения и соседние сборки не затрагиваются.

Не входят: фоновая автоматика, новые настройки, delta updates, ручной менеджер
кеша, выбор каналов, пользовательский сервер, аналитика, собственный установщик,
собственные поля пароля и отключение системных проверок безопасности.
Предлагаемое выше исключение Library Validation ограничено bundle приложения
и не считается разрешением на отключение Gatekeeper или других защит.

## Приёмка после разрешения реализации

- [ ] Настоящий переход A → B между двумя updater-enabled сборками: проверка,
  скачивание, подпись, установка в тот же путь, один новый процесс с build B.
- [ ] Одинаковый/меньший build не предлагается; более новый build с той же
  marketing version обрабатывается правильно; неподходящая система исключена.
- [ ] Offline, отсутствующий feed, повреждённый feed/архив и неверная подпись
  не становятся «обновлений нет» и не приводят к установке.
- [ ] Проверены прерывание загрузки, нехватка места, read-only/translocated
  расположение, отказ в правах и восстановление при прерывании замены.
- [ ] Проверены Cancel на каждой доступной стадии, Escape/крестик, обычный Quit
  после согласия на установку и немедленный Install and Relaunch.
- [ ] Все сохранённые настройки/история совпадают до и после; последняя принятая
  запись не теряется; скрытая и незакреплённая позиции восстанавливаются только
  для ожидаемого update-relaunch; отмена не оставляет ложную запись восстановления.
- [ ] При отмене завершения/ошибке ожидания записи Black Hole продолжает
  получать квоту; возобновлённый App Server не создаёт ложную непрерывность.
- [ ] Ноль/неизвестная/устаревшая квота и потеря связи с Codex не блокируют
  updater; изменения updater не вызывают quota refresh и не останавливают задачи.
- [ ] Проверены RU/EN, клавиатура, VoiceOver, Reduce Motion, без-Dock accessory
  lifecycle, fullscreen, несколько экранов, hidden/click-through pet.
- [ ] Нет фоновых запросов обновления при старте/повторном старте; один controller
  не создаёт параллельные циклы; в штатном окне нет включения автоустановки.
- [ ] Воспроизводимо подписаны и опубликованы архив/feed; ключи отсутствуют
  в поставке/логах; совместимые записи feed сохранены; bootstrap объяснён.
- [ ] Первая ручная установка и последующий встроенный переход проверены именно
  для ad-hoc канала без Developer ID. Проверены загрузка Sparkle, подписи всех
  вложенных компонентов и поведение Gatekeeper; системная защита не отключается.

## Граница реализации и проверки

Расположение команды, ручной запуск, полный сценарий установки и ограниченное
исключение Library Validation согласованы. Developer ID не требуется.
Реализация включает зависимость и необходимые изменения packaging; постоянный
ключ, публикация feed и выпуск переходной версии требуют отдельного задания.
Проверка окон и A → B на тестовых копиях требует отдельного согласия на GUI
согласно workspace AGENTS.md. Непроверенные критерии выше остаются открытыми.
