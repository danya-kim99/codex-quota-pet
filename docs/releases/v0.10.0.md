Manual application updates from GitHub for Apple silicon Macs running macOS 14
or newer.

## New in this release

- **Check for Updates… / Проверить обновления…** is available before Quit in the
  native menu bar, including while the pet is hidden or ignores pointer input.
- The native updater shows the available version and release notes, downloads
  and verifies the update, and installs it on request. Install and Relaunch
  restarts immediately; dismissing a prepared update may defer installation
  until normal Quit.
- Both the update feed and application archive require Ed25519 signatures.
  Updates use GitHub Releases and preserve saved preferences and quota history.
- Update termination waits for accepted history writes. A failed or timed-out
  save keeps the current application running and resumes quota collection.

## Compatibility and privacy

This remains an arm64-only ad-hoc preview for macOS 14 or newer. Developer ID
signing and notarization are not included; macOS security confirmation may still
be required. No system security setting is disabled.

Update checks are manual. Automatic checks, unattended future updates, system
profiling and JavaScript release notes are disabled. GitHub receives ordinary
request metadata; quota, history, prompts, projects and account identifiers are
not sent to the update service.

## Install from version 0.9.0 or earlier

The first updater-enabled version requires one manual installation:

1. Download `Black-Hole-Codex-Quota-Indicator-v0.10.0-macos-arm64.zip` and the
   matching `.sha256` file from this release.
2. Verify the checksum and unzip the archive.
3. Quit Black Hole and replace its copy in `/Applications`.
4. Open the new version. Future releases can be installed from Check for Updates.

## Verification boundary

Focused headless checks cover signing configuration, history writes, termination
failure recovery and one-use restoration data. A separate signed test copy was
downloaded and replaced from build 9001 to 9002 by the native Sparkle installer;
the installed bundle passed strict signature verification.

The release workflow additionally runs the complete macOS test suite and checks
the final bundle, signed feed and published asset digests. Native window
interaction, cancellation, actual application relaunch, VoiceOver and Gatekeeper
remain unverified in this headless preparation.
